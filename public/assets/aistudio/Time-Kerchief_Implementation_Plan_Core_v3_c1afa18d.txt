IMPLEMENTATION PLAN

1. DELIVERY GOAL
Ship two working curated journeys using the same dial and stage/media components. Each journey connects images, selected videos, verified label details, workers/skills, technology and a short learning check. No simulation, production decision challenge or hypothetical forward replay is part of this plan.
Assumption: four people and about 24 build hours. Confirm actual BVP rules/duration before adopting this schedule. No implementation role assignment below is a claim about a member's skills.

Ayush Bhatt is team leader and coordinates scope, integration and demo acceptance.

6. RELEASE CHECKLIST
Functional: T01-T15. Resilience/privacy: T16-T17. Performance/accessibility: T18-T19. Integrity/security: T20-T21. Stretch comparison: T22 only if included.
Record results with device/browser, test date, build/content version, pass/fail and brief evidence. Test actual video stop behaviour, not only the absence of a visible player. Review rights/source metadata manually.
A remaining failure in required content accuracy, core navigation, quiz scoring, keyboard access or offline readiness blocks the claim that the core MVP is complete.

7. CONTINGENCIES AND CUT ORDER
Cut first: optional comparison/per-serve toggle, extra videos, extra practice questions, custom animation and decorative scenes.
Do not cut: two verified primary products; stage image/text; workers/technology context; at least one video resource per journey; evidence access; short checks; basic accessibility and cached core.
Embed blocked: use external link plus summary. Image source unsuitable: use an original permitted illustration labelled as generic. Tag unavailable: select another labelled garment. Network down: cached image/text demo; honestly explain remote video cannot play.
Dial drag bug: use working tap/keyboard/buttons while fixing; do not declare T04 passed if drag remains required and broken. Offline failure: fix or disclose incomplete status; a recorded demo does not establish offline support.

8. WORKING AGREEMENTS
Main branch remains buildable. Schemas merge first; UI uses matching fixtures until content arrives. Small PRs with one reviewer, separate folders and a named owner for shared routes. Run validation/typecheck/tests/build before merge. No late feature additions after freeze.

9. DEMO SCRIPT
Open garment -> rewind to fabric formation -> inspect before/after transformation and image -> play its video -> show worker task/skill and machinery note -> open actual garment evidence and care explanation -> answer a short learning check -> show local result.
Open biscuit -> rewind to baking/mixing -> show different media/content in the same component -> inspect one verified label fact and its source -> explain how this teaches workers/innovation without claiming real factory impact.
State clearly that the process is typical, the label facts are verified for the demo item, and videos may be third-party resources.

10. POST-EVENT VALIDATION
Run the PRD exploratory pilot; collect consent-appropriate feedback without unnecessary personal details. Record observed confusion and actual pre/post responses; report small-sample limitations. Prioritise fixes based on these findings before considering simulations, dashboards or AI additions.
